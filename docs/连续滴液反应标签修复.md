# 连续滴液反应标签修复

移液管与滴定管共用 MeteredTransfer.Move → Lab.Settle → 反应事件链。
原来的 RecentReactions 历史虽限定 24 条，LabBootstrap 每帧消费新事件后仍持续创建
EquationTag，因此十秒显示期内能累积数百张标签；每张标签的 Sync 又在排布过程中
重复执行全局 Canvas.ForceUpdateCanvases 和文本测量。

## 修复范围

- 按容器、方程式、条件、反应物/生成物系数及可逆/有机标识识别重复显示。
- 同一反应复用原标签，仅更新最新事件和显示截止时间；不合并或丢弃化学反应量。
- 每容器最多六张不同方程式，全局最多二十四张；重新编号槽位，不留下不断升高的空槽。
- 缓存标签排版、容器标签引用和投影角点；语言/离子式显示切换仍使排版失效重建。
- 取消 EquationTag.Sync 内的全局 Canvas 强制刷新。关闭显示时不生成隐藏标签。

## 验证

显式 `-reactionTagTest` 的独立后台 Player，记录到 `Logs/reaction-tag-audit.txt`。
移液管、滴定管各连续 240 次转移：均只创建一张标签，排版一次；检查反应物消耗、
转移体积、语言切换重排、最后一滴后超时、不同反应上限和关闭标签，共 16 项通过。
SyncViews 平均耗时分别约 0.720ms / 0.737ms；这只是该测试场景的视图同步耗时，
不是完整帧时间或所有化学/流体场景的性能承诺。

完整交互回归输出 `Logs/reaction-tag-regression.log` 和 `Logs/interaction-regression.txt`。
