# 定向输入管道退出修复

2026-09-27，教师主目录 `D:\ChemLabUnity`。

原 `WindowTargetInput` 后台线程使用同步 `WaitForConnection` / `ReadLine`，主线程在 OnDestroy 中直接 Dispose 同一管道。多次控制台专项虽然所有断言通过，退出却停在 Shutdown，需要清理自有测试进程。

现使用异步（overlapped）管道，后台线程轮询异步连接/读取任务与停止信号；停止后由后台线程关闭管道并观察任务完成，主线程只发停止信号并最多 Join 一秒。OnApplicationQuit 和 OnDestroy 共用幂等关闭入口，不改变协议或实验操作，不碰桌面鼠标键盘。

首轮实现曾提前 Dispose Task 自有 AsyncWaitHandle，导致 Mono 连接回调访问已关闭句柄，无客户端场景退出崩溃（-1073741819）。证据保存在 `Logs/pipe-shutdown-first-failure.log`。最终实现改为观察 Task 完成，不再获取/释放其内部等待句柄；失败版本已被替换，未将首轮当成通过。

## 最终验收

`tools/pipe_shutdown_test.ps1` 启动三个隐藏 Player，各有独立临时目录和日志，客户端保持打开直到 Player 自行退出；总超时才清理自有进程。覆盖：

- unconnected：从未连接客户端，覆盖挂起的连接等待。
- idle-client：已连接但不发数据，覆盖读取等待。
- partial-line：发送 `MOVE 100` 而无换行，覆盖 StreamReader 半行等待。

三组各自控制台 **143/143**，**自然退出 0**，没有一秒 Join 警告；测试脚本自身退出 0，finally 无需终止这些已结束进程。日志完整复制至 `Logs/pipe-shutdown-final-evidence/` 各子目录。`Logs/pipe-shutdown-final-build.log`：Succeeded，错误 0。教师 Build 与源码同步，没有更新学生端、教师副本或发布包。

这解决 Windows 团结运行时已复现的退出问题，不等于 macOS 管道或全部平台已经验收。
